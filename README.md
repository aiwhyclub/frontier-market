# Frontier Market

**도제 경험에서 얻은 암묵지를 AI 학습·평가용 데이터와 가상회사 환경으로 연결합니다.**

- 상태: 확정 (제품 문서의 구축 기준 및 영상 스토리; Build 별도)
- 변경 원칙: 이후 수정사항은 구축 과정에서 관련 문서에 함께 반영한다.
- 현재 단계: 기획·설계·개발계획 확정; 로컬 검수 기록과 화면·공개 검수 구분
- 기준일: 2026-10-24 (Asia/Seoul)

## 프로젝트 소개

Frontier Market은 숙련자의 판단 기준, 감각적 단서, 예외 대응을 발굴하고 전문가 평가·자료 정제·사람 검토를 거쳐 AI 학습·평가에 활용할 수 있는 자산으로 만드는 프로젝트입니다. 산업현장뿐 아니라 공예·예술·요리 등 도제 경험으로 지식을 익히는 분야를 포함합니다.

자료의 출처와 이용 범위, 전문가의 경험, 작업의 검토 이력을 하나의 흐름으로 연결합니다. 기업에는 **무료 AX(AI 전환)**를 제공하는 원칙으로 현장 시스템 구축·컨설팅(FDE)을 관리하고, 검증된 작업을 가상회사 데이터와 작은 업무 실행 환경으로 구성하는 것을 목표로 합니다.

주요 대상은 AI 학습·평가 데이터와 업무 환경이 필요한 **Frontier AI Lab·모델 평가팀·데이터 구매 담당자**입니다. 초기 제품은 운영자가 같은 컴퓨터에서 자료·전문가·프로젝트를 관리하는 내부 도구로 계획했습니다.

## 7단계 업무 흐름

| 단계 | 주요 업무 | 계획한 결과물 |
|---|---|---|
| 1. 자료 수집·체계화 | 공개 웹·클라우드 공유 URL의 텍스트와 직접 입력 자료 등록 | 출처·수집 시각·원문이 연결된 자료 |
| 2. 영구 DB 구축 | 자료·전문가·작업·프로젝트 저장, 검색 및 연결 조회 | 작업을 이어갈 수 있는 영구 기록 |
| 3. 전문가 모집·평가 | 후보 등록, 운영자 평가·승인, 승인 전문가의 원시 작업 등록 | 평가 근거와 원시 작업 기록 |
| 4. 카탈로그 제작 | 주제별 자료·전문가·작업 연결 | 근거와 대상 능력이 정리된 주제 카드 |
| 5. 작업 정제·검증 | 맥락·관측 단서·판단·예외·결과 정리, 교정 및 사람 검토 | 검토 이력과 이용 범위가 연결된 작업 |
| 6. 무료 AX·FDE 관리 | 기업 프로젝트의 범위·진행 단계·산출물 관리 | 작업·카탈로그와 연결된 현장 프로젝트 기록 |
| 7. 가상회사 구축 | 검증된 작업으로 데이터 패키지와 작은 업무 환경 구성 | 조직·업무 자료·과제·평가 기준 및 허용 JSON 내보내기 |

구매자 후속 기록은 **샘플 검토 의견·유료 파일럿 조건 논의·필요 주제 추천**의 세 유형을 모두 포함합니다. 기업 AX 비용 0원은 구매자 대금·전문가 보수와 구분합니다.

## 가상회사 데이터와 업무 환경

가상회사는 모델이 업무 맥락을 읽고 판단하는 과정을 학습하거나 평가할 수 있도록 설계한 데이터와 작은 업무 시뮬레이터입니다.

- **업무 맥락:** 회사·조직과 업무 자료
- **판단 과제:** 관측 정보, 선택 가능한 행동, 기대 답안과 평가 기준
- **추적 정보:** 원천 자료, 전문가·사람 검토, 목적별 이용 범위
- **실행 환경:** 과제 실행·결과 확인·초기화와 반복 체험

첫 합성 사례는 가공품의 표면 이상을 보고 원인을 단정하지 않은 채 추가 점검을 요청하는 판단을 다룹니다. 점검 전 출하를 막고 점검 후 가능한 행동과 결과를 보여주는 흐름을 계획했습니다. 실제 LLM 훈련이나 모델 성능 측정은 현재 구축 범위에 포함하지 않습니다.

## 화면 구성

하나의 반응형 웹에서 대시보드와 7단계 작업 공간을 구성하도록 설계했습니다. 아래 표는 운영자의 전체 업무를 기준으로 하며, 공개 방문자에게는 시연 권한만 적용합니다.

| 화면 | 역할 |
|---|---|
| S0 대시보드 | 전체 현황·검토 대기·최근 활동·다음 작업 |
| S1 자료 수집 | URL·텍스트 등록과 출처 확인 |
| S2 데이터베이스 | 기록 검색·상세 조회·연결 탐색 |
| S3 전문가 | 후보 등록·평가·승인·원시 작업 업로드 |
| S4 카탈로그 | 주제 카드 작성·자료 연결·구매자 의견 |
| S5 정제·검증 | 작업 구조화·교정·권리 확인·사람 검토 |
| S6 AX·FDE | 무료 AX 프로젝트와 진행 기록 관리 |
| S7 가상회사 | 패키지 생성·샘플 확인·과제 실행·JSON 내보내기 |

Web·Mobile 반응형을 대상으로 하며, 설계 검수 폭은 320·375·768·1024·1440px입니다. 실제 제품 시안 제작과 화면 검수는 구축 단계에서 진행합니다.

## 데이터와 검토 원칙

- **사람이 최종 판단합니다.** 전문가 평가와 작업 검토를 별도로 기록하며 점수만으로 자동 승인하지 않습니다.
- **목적별 이용 범위를 확인합니다.** 원천 자료·전문가 제공 동의·작업의 허용 범위를 함께 검사하고, 미확인·만료·철회 또는 관련 승인 취소 시 영향을 받는 생성·추가 내보내기를 보류합니다.
- **이력을 보존합니다.** 원문·교정본·검토 기록과 가상회사 스냅샷을 구분하고, 내보내기 직전에 현재 권리·검토 상태를 다시 확인합니다.
- **연결 관계를 검사합니다.** 가상회사 생성에는 카탈로그·FDE 프로젝트 연결과 작업 관계의 일치가 필요합니다. 현장 프로젝트의 완료 여부나 진행 단계 자체는 생성 차단 조건이 아닙니다.
- **개발·시연 자료의 범위를 제한합니다.** 합성 사례와 이용 범위를 확인한 공개 연습자료를 사용합니다. 공개 시연에는 합성 자료만 노출하며 실제 고객·비공개·식별 가능한 전문가 자료는 사용하지 않습니다.

첫 버전은 **수동·규칙 기반 처리**를 사용합니다. 실제 AI 연동·외부 모델 전송·AI API 지출은 보류하며, 키나 모델 설정만으로 호출하지 않습니다. 자료 구조화·작업 정제는 향후 AI 도입의 우선 대상으로 유지합니다.

아래는 확정된 구축 기준입니다. 실행 환경과 의존성 준비는 별도 Build 요청 후 첫 개발 작업에서 진행합니다.

| 기본 운영 | 같은 컴퓨터에서 사용하는 내부 운영 도구 |
| 기기 대응 | Web·Mobile 반응형 |
| 공개 시연 | 별도 호스팅·접근 보호·방문자 분리·종료 차단 검증 후 조건부 진행 |

외부 전문가·구매자용 계정과 로그인은 첫 버전 범위에서 제외합니다.

## 개발 상태와 계획

**기획·설계·개발계획은 확정했습니다.** 제품 기준 9개 문서 외에 2분 50초 소개 영상용 스토리와 별도 작업자의 로컬 검수 기록이 추가됐습니다. [로컬 수용 검수 기록](docs/acceptance-local.md)은 보고서 작성 시점의 서버 테스트·GET 확인과 미실행 항목을 구분합니다. 이후 확인 결과도 해당 범위를 구분해 해석합니다. 이 문서·영상 스토리 작성에서는 Build·앱/서버 실행·실제 AI 호출·배포를 수행하지 않았습니다.

| 구분 | 확정 범위와 상태 |
|---|---|
| 기능 명세 | 필수 49개·선택 7개, 총 56개 기능 ID |
| 전체 개발계획 | 13 EPIC·70 STORY — 실제 진행·완료는 개발계획과 검수 기록에 따라 확인 |
| 1차 연결 목표 | EPIC 10까지 54 STORY |
| 로컬 필수 완료 범위 | 60 STORY — 1차 목표 이후 필수 6개 포함 |
| 해커톤 공개 시연 | 조건부 후속 범위 3 STORY |
| 보류 선택 기능 | 실제 AI 6개·가정 손익 보조 1개 |

개발계획은 STORY 1.1에서 전용 가상환경·의존성·포트·DB 경로를 준비하도록 구성했습니다. 최초 문서 감사 당시의 기존 코드는 중단 초안이었으며, 이후 로컬 구현에 대한 확인 결과는 별도 수용 검수 기록에서 범위와 한계를 확인합니다. 서버 테스트·GET 응답만으로 화면·공개 시연 검수까지 완료했다고 해석하지 않습니다. 후속 Build·실행·배포는 해당 작업의 별도 지시에 따릅니다.

## 해커톤 공개 시연 계획

기간 한정 공개 웹 시연을 후속 구축 범위에 포함했습니다. **현재 공개 페이지나 배포 링크는 준비되지 않았습니다.**

| 접근 구분 | 허용 범위 |
|---|---|
| 공개 방문자 | 합성 시연자료 조회, 방문자별로 분리된 과제 실행·초기화 |
| 보호된 운영자 | 자료 등록·수정, 권리 확인·승인, 가상회사 생성·JSON 다운로드 등 운영 업무 |

공개 종료 기준은 **2026-10-24 21:00 한국시간(12:00 UTC)**입니다. 종료 시각부터 공개 화면·API 접근을 차단하고 DB를 보존하도록 설계했습니다. 해당 시각이 지난 뒤에는 새 공개 배포나 재공개를 시작하지 않습니다.

실제 공개 전에는 호스팅·비용·운영자 접근 보호·방문자 세션 분리·영구 저장과 백업·종료 차단을 확인합니다. 이 준비는 로컬 구축 착수의 선행 조건으로 요구하지 않습니다.
