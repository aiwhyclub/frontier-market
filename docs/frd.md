이 수는 사용자 행동 단위의 명세 집계다. 실제 개발에는 환경 설정·데이터 준비·접근성·통합 검수 작업이 더해지므로 개발 작업 수·기간과 같지 않다. 복잡도는 PRD와 같은 **큼**이다. 영구 저장과 참조, 사람의 상태 전환, 목적별 권리 교집합, 버전 검토, 불변 스냅샷/가변 환경, 반응형 동등 기능이 연결된다.

범위를 줄이는 결정은 하지 않았다. 검토할 수 있는 축소 후보는 다음 순서의 **제안만** 남긴다. 사용자가 채택하기 전에는 위 집계·필수 범위를 바꾸지 않는다.

1. F2.3의 복합 상태/분야 필터를 단순화하면 정교한 목록 비교가 줄어든다. 기본 검색·목록·상세는 유지해야 한다.
2. F4.4의 선택 media_refs 편집을 단순 참조 메모로 시작하면 매체별 시점·설명을 세밀하게 나누지 못한다. 도제 맥락·단서·판단·근거는 유지해야 한다.

첫 버전의 필수 49개 흐름은 수동 입력·규칙 기반 초안으로 수행한다. C-06 A로 실제 AI 연동·외부 모델 전송·API 지출을 보류하며 키·모델 설정만으로 호출하지 않는다. 선택 F10의 미채택과 F6.5의 채택 여부가 전문가 모집·FDE·가상회사 업무 자체를 선택 기능으로 미루지 않는다. C-01의 같은 컴퓨터에서 사용하는 로컬 내부 도구와 로컬 JSON 내보내기의 권리·검토 재검사를 유지한다.

C-07 B와 추가 권한 A로 해커톤 후속 확장은 합성 자료 조회·과제 실행/초기화만 허용하는 실제 동작 공개 웹시연이다. 공개 종료는 2026-10-24 21:00 KST(12:00 UTC)이며 이 시각부터 새 공개 UI·API 접근을 서버에서 차단하고 DB·검토 이력·스냅샷은 보존한다. 등록·수정·권리 확인·승인/취소·재검토·회사 생성·다운로드는 운영자 보호 기능이다. 공개 실행/초기화는 방문자별 분리 합성 시도만 변경하며 운영자·다른 방문자의 상태와 snapshot은 보존한다. 외부 전문가·구매자 계정은 추가하지 않는다. 호스팅·운영자 보호·방문자 분리 기술은 EPIC 13 착수 및 공개 전 준비사항이며 로컬 기본 구축 시작을 막지 않는다. 별도 Build 요청 전에는 실제 구축·배포하지 않는다. 공개 시연 확장은 기존 필수49/선택7 기능 ID를 변경하지 않는다.

## ① 요약·역할·화면 대조

산업현장 또는 다른 분야에서 도제 경험으로 얻는 암묵지를 자료→사람→과제→검토→데이터·환경으로 연결한다. 근속·직함·도제 경험만으로 정확성을 보증하지 않으며 관측 단서·판단·예외·결과 확인을 기록한다. 기업 AX 비용은 0원이다. 저장·승인·시연과 실제 모집·현장 수행·권리 확보·사업성을 구분한다.

### 역할

| 역할 | 명세의 행동·한계 |
|---|---|
| 운영자 | 자료·후보·카탈로그·프로젝트·의견을 등록/연결. C-01에서 확정한 같은 컴퓨터의 내부 운영 범위에서 대리 입력 가능 |
| 평가/검토 담당 | 점수·판정·근거·권리 확인을 기록. 실제 적격성과 독립성은 별도 확인 |
| 전문가 | 승인 후 원시 작업 제공의 주체. 첫 버전에는 별도 로그인 계정 없음 |
| 구매자/심사위원 | 샘플·근거·목적별 범위 확인, 세 유형 의견. 내부 운영 도구에서는 운영자가 의견을 대신 입력 |

C-07 B의 공개 방문자는 합성 자료 조회·자신의 분리된 합성 과제 실행/초기화만 할 수 있다. 내부 운영자의 등록·수정·권리 확인·승인/취소·재검토·회사 생성·다운로드 권한을 부여하지 않으며 직접 API 요청도 거절한다. 공개 화면·응답에는 합성 자료만 노출하고 종료 시각부터 새 UI·API 직접 접근을 차단한다. 방문자 구분·운영자 보호 기술은 EPIC 13 착수 및 공개 전에 확인하며 외부 전문가·구매자 계정을 추가하지 않는다. 이 공개 준비는 로컬 기본 구축의 선행 조건이 아니다.

한 로컬 사용자가 역할 이름만 바꾼 것을 독립 심사로 표시하지 않는다. 외부 전문가·Lab의 직접 로그인, 실제 모집 연락·계약·지급·현장 설치·LLM 훈련은 별도 범위다.

점수 의미는 0=현재 자료로 확인 불가, 1=개략적 설명, 2=구체 사례로 설명, 3=사례·근거·한계까지 설명이다. 0점은 능력 부재 판정이나 미입력을 뜻하지 않는다. 지정 운영책임자 1명이 근거를 확인해 승인/보완/반려를 최종 판정한다. 최종 평가에는 4축 점수·판정·사유·평가자·일시가 필수이며 미입력과 0점을 구분한다. 재평가는 새 기록으로 남긴다. 후보 승인과 개별 작업의 사람 검증·권리 확인은 별개이고 미승인 업로드는 화면과 서버 모두 차단한다.

C-05 A로 지정 운영책임자1명이 아래 판단을 책임지며 각 행동은 별도 기록한다. 담당 표시가 계정 인증·독립 심사나 실제 이용 허락을 대신하지 않는다. C-04의 합성 가공 사례·허용 공개 연습자료 범위와 실자료 도입 전 별도 결정은 유지한다.

1. 권리 증빙 확인: 대상 버전/내용 해시와 원 권리자·제공자의 허용 근거, 목적·파생/배포·기간/제한, 확인 사유·담당자·일시를 기록한다. 합성 동의는 연습용 예시로 표시한다.
2. 작업 검증: 검토한 버전/입력 해시에 판정·사유·근거·검토자·일시를 연결한다. 권리 기록만으로 작업을 승인하지 않는다.
3. 취소와 보류: 권리 상태 변경과 작업 승인 취소를 구분한다. 과거 작업 승인은 특정 승인 사건과 그 검토 버전을 지정하고 사유·근거·담당자·일시를 남긴다. 그 승인을 사용하는 현재 작업의 생성과 해당 승인을 포함한 패키지의 추가 내보내기만 HOLD다. 다른 유효한 승인과 과거 기록/스냅샷을 함께 지우거나 취소하지 않는다.
4. 재검토: 보완 근거를 확인한 뒤 새 사람 검토를 기록한다. 새 승인만으로 취소된 과거 승인이나 그 승인을 사용한 패키지를 자동 복구하지 않는다.

record version은 개정 번호, material_hash는 실제 내용, input_hash는 사람 검토 입력의 식별값이다. 권리는 대상 내용과 연결하고 사람 판정은 검토 입력·승인 사건과 연결한다. 상태 저장으로 개정 번호만 증가하고 input_hash가 같으면 취소되지 않은 기존 유효 판정을 유지한다. 해시 동일성만으로 취소 사건이나 권리 HOLD를 해제하지 않는다.

## ③ 핵심 대표 시나리오 2개

### 시나리오 A — 빈 DB에서 전문가 원시 업로드와 검증 작업까지

- **시작 조건:** 운영자, 자료/카탈로그가 없는 상태도 허용. C-04 범위의 합성 본문·후보 정보 또는 이용 범위 확인된 공개 연습자료가 있다.
- **정상 흐름:** S1에서 URL/본문 저장→S3 후보 등록·점수/판정/메모로 승인→catalog_id 없이 원시 작업 업로드→S4 자료·사람·업로드를 과제에 연결→S5 원문/초안 비교·사람 교정 저장→최신 버전의 근거와 메모로 사람 승인.
- **대표 예외:** URL 실패는 본문 입력으로 계속. 미승인 업로드는 저장 거절. 카탈로그 미연결이면 업로드는 보존하되 정제 전 연결 안내. 현재 초안은 규칙 기반이며 처리 실패에는 수동 교정으로 계속한다. 교정 후 예전 검토를 승인처럼 재사용하지 않는다.
- **완료 기준:** 원천·전문가·카탈로그가 연결된 최신 작업에 사람 판정이 저장된다. 이 완료가 권리/실제 전문성까지 입증하지는 않는다.
- **데이터 변화:** source/전문가/평가/원시 work/catalog와 정제 새 버전·validation·activity/review event 생성. 과거 원문/초안 보존.
- **사용자가 보는 결과:** S2 연결 자료, S3 승인/업로드, S4 카드, S5 원문·교정·최신 검토. 평가·생성 방식·합성 표시를 볼 수 있다.

### 시나리오 B — 검증 작업에서 회사 데이터·환경·세 의견까지

- **시작 조건:** 시나리오 A의 최신 승인 작업, 연결 카탈로그·FDE 프로젝트의 관계 일치, 근거·전문가 승인과 요청 목적/파생·배포 허용 확인. 프로젝트 연결은 필수지만 현장 완료/진행 단계 자체는 생성 게이트가 아니다.
- **정상 흐름:** S6에 무료 AX 범위·단계·산출물을 기록/확인→S7 name·work_ids·purpose를 선택→조건별 게이트 재확인→snapshot 생성·샘플 확인→task 선택·검사 요청 후 해제→선택 task reset·재시도→현재 권리 확인 후 JSON 다운로드→S0/S4/S7에서 운영자가 세 의견 유형을 각각 기록하고 처리 상태·보완 대상 연결을 수정·저장·재조회.
- **대표 예외:** 사람 검증·권리 미확인/만료·평가 전용 training은 HOLD와 보완 폼 안내. 검사 전 해제는 차단. 원문 단순 개정은 기존 본문을 수정하지 않음. 과거 권리/검증 취소는 기존 snapshot 감사 보존+추가 export HOLD. 회사가 없어도 새 topic 기록 가능.
- **완료 기준:** 올바른 목적의 데이터·고정 snapshot과 선택 task 실행/복원, 허용된 export, 세 의견과 수정한 처리 상태·보완 연결이 저장·복원된다. 실제 LLM 학습·거래·현장 성과로 표시하지 않는다.
- **데이터 변화:** company/version/snapshot·현재 authorization·task runtime/시도 이력·feedback/follow-up refs 기록. reset·원문 개정은 기존 snapshot을 갱신하지 않음.
- **사용자가 보는 결과:** 생성 목적·근거·검토/권리 상태, 작업별 과제·환경 결과·초기화, 패키지 버전·다운로드/차단 이유, 의견 저장 결과.

## ④ 데이터별 CRUD 점검

CRUD는 만들기(C)·보기(R)·고치기(U)·지우기(D)다. **PRD가 삭제를 확정하지 않았으므로 D를 새 기능으로 추가하지 않는다.** 아래 D의 ‘미정/현재 제공 범위 없음’은 영구 삭제 금지를 확정했다는 뜻도 아니다. C-04 A로 현재는 합성 가공 사례와 이용 범위를 확인한 공개 연습자료만 다루며 실제 고객·비공개·식별 가능한 전문가 자료는 제외한다. 실제 파일럿의 자료·권리·보존기간·삭제/비식별 방식은 도입 전 별도 결정한다. 현재 버전/감사 기록 보존을 실자료의 무기한 보존으로 해석하지 않으며 삭제를 대신하는 새 아카이브 기능도 자동 추가하지 않는다.

| 원문/버전 불변·현재 상태 분리·낙관적 충돌 확인 | 과거 검토와 새 개정을 혼동하지 않음 |
| 민감 오류/로그 제한·향후 AI 비밀키 서버 보관 | 현재 API 키 없이 동작하며 향후 연동해도 브라우저·응답에 자격증명 노출 방지 |
| 외부 자료를 비신뢰 입력으로 취급 | 원문 안의 명령·허구 승인으로 시스템 정책을 바꾸지 않음 |
| 안전한 URL 범위·시간/크기 제한 | 수집 실패·내부 주소 접근·과대 입력 제어. 수치는 TRD 제안값 |
| label·포커스·키보드·오류 설명·색 외 상태 표시 | Web/Mobile에서 같은 핵심 행동을 이해·복구 |
| 금액·시간 표현 일관성 | 통화 단위 혼동·0가격 나눗셈·시각 오인을 방지. TRD로 수치 표현 지정 |

기술 표준은 별도 사용자 선택 질문으로 만들지 않는다. C-01의 로컬 내부 운영을 유지하고 C-07 B의 기간 한정 공개 웹시연은 후속 확장으로 구분한다. 합성 자료·서버의 종료 시각 검사·공개 조회/분리 과제 체험과 운영자 보호를 적용하며 외부 전문가·구매자 계정을 추가하지 않는다. 호스팅·운영자 보호·방문자 분리 기술은 EPIC 13 착수 및 공개 전에 확인하며 로컬 기본 구축 시작을 막지 않는다. 실제 구축·배포는 별도 Build 요청 이후에만 진행한다.

## ⑧ 공통 입력 검증·오류·권한

- 필수 문자열은 공백만 입력하면 저장하지 않는다. URL/본문 둘 다 없으면 입력을 요청하고 잘못된 URL·지원하지 않는 형식은 이유를 표시한다. 원문·근거 최대 길이와 요청 제한은 TRD 기준이며 사용자 내용은 오류 시 유지한다.
- 지정 운영책임자는 전문가의 최종 평가에서 C-02의 공통4축 0~3점·판정·사유·평가자·일시를 기록한다. 미입력은 0점으로 대신하지 않고 합계는 참고용이며 고정 합격선·자동 승인을 만들지 않는다. 원시 업로드는 승인 전문가 필수·카탈로그 선택, 정제/생성은 카탈로그 필수다.
- purpose는 training/evaluation, work_ids는 비어 있지 않은 ID 목록이고 회사 생성의 project_id는 필수다. 연결 프로젝트·카탈로그·모든 선택 작업의 관계를 검사하며 누락/불일치는 S6 등록·연결 폼으로 안내한다. 프로젝트 진행 단계 자체는 생성 차단 조건이 아니다. feedback.kind는 sample_review/pilot/topic이며 새 topic의 대상 ID는 계속 선택이다.
- 정제 교정은 새 버전·사유를 저장하고 최신 검증 대기로 전환한다. 사람이 검토한 input_hash와 현재 검토 입력 해시가 다르면 재검토를 안내한다. 상태 저장으로 record version만 증가하고 input_hash가 같으면 취소되지 않은 기존 유효 판정을 유지한다. 해시 동일성만으로 승인 취소나 현재 권리 HOLD를 해제하지 않는다. 현재 개정과 과거 승인 취소를 동일 처리하지 않는다.
- S1 자료 상세·S5 작업 상세의 운영자 전용 ‘원문·근거 개정’은 현재 내용을 편집 폼으로 복사하고 개정 사유·담당자·일시와 함께 새 버전을 저장한다. 과거 원문·근거·검토 기록·snapshot은 덮어쓰지 않고 변경된 검토 입력을 재검토로 전환한다. 공개 방문자는 개정 폼·직접 API를 사용할 수 없다.
- 생성·export는 모든 관련 목적/파생/배포·전문가·검토 조건을 서버에서 재검사한다. 부족 조건별로 ‘어디에서 무엇을 확인할지’를 안내하며 임의 active 전환으로 우회하지 못한다.
- C-06 A로 현재 초안은 수동/규칙 기반이며 키·모델 설정만으로 실제 AI를 호출하지 않는다. 외부 모델 전송·API 지출은 보류한다. C-07 B 공개 시연도 이 규칙과 합성 자료만 노출하는 조건을 유지한다. 로컬 JSON 다운로드에는 기존 권리·검토 조건을 검사하며 이를 공개 방문자의 다운로드 권한으로 자동 해석하지 않는다.
- C-07 B의 공개 방문자는 합성 자료 조회·자신의 분리 합성 시도 run/reset만 허용한다. 등록·수정·권리 확인·승인/취소·재검토·회사 생성·다운로드는 운영자 보호 대상으로 UI·직접 API에 동일하게 적용한다. 공개 run/reset은 운영자·다른 방문자의 상태·고정 snapshot을 바꾸지 않는다. 새 공개 접근은 서버 시각이 2026-10-24T12:00:00Z 이상이면 차단한다. UI 숨김이나 클라이언트 타이머만으로 대신하지 않으며 종료 시 DB·원문·검토/취소 이력·스냅샷을 삭제하거나 초기화하지 않는다. 방문자 구분·운영자 보호 기술은 EPIC 13 착수 및 공개 전 준비사항이며 로컬 기본 구축의 선행 조건이 아니다.
- 금액은 통화와 함께 입력하고 유효한 숫자/비음수 제안값을 검증한다. 실제 가격을 권고하지 않는다. company_ax_fee는 0, 가격이 0인 이익률은 null이다.
- 저장 중 중복 버튼을 막는다. 실패와 성공을 구분해 안내하고 입력을 보존한다. 이미 성공한 동작의 재시도 중복은 알려준다. 임의의 외부 연락·결제는 발생하지 않는다.
- 로컬에서 운영/검토 역할의 입력을 대신할 수 있다. 전문가 승인 상태·사람 검증·현재 이용 범위는 서버 규칙이며 화면 이름이나 AI 응답으로 변경하지 않는다. 실제 Lab 계정·로그인을 새로 추가하지 않는다.
- 320/375/768/1024/1440px에서 동일 접근 모드·역할의 허용된 핵심 필드/행동을 동등하게 제공한다. 공개 방문자에게 운영자 전용 쓰기·승인·다운로드를 노출하지 않는다. 데스크톱 표는 모바일 카드, 원문/상세/폼은 전체 화면/탭으로 전환한다. 고정 하단 행동은 safe-area·가상 키보드·본문 여백을 반영하며 44px 터치·포커스 복귀를 점검한다.
- 초기화는 선택 task의 실행을 새 시도로 복원한다. 패키지·원천·이전 감사 이력·의견을 삭제하는 전체 초기화로 해석하지 않는다.
