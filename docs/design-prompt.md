## 1. 공통 스타일 가이드

기존의 차분한 작업 공간 무드를 유지한다. 탐색은 남색 `#172c3a`, 주요 행동은 청록 `#1e6b60`, 배경은 크림 `#f7f5ef`, 내용 표면은 흰색이다. 본문 `#1d2c2b`, 보조 정보 `#5c6765`, 보류·주의 `#9b5627`, 오류 `#a63b36`을 사용한다. 일반 텍스트 대비는 4.5:1 이상, 필수 경계·포커스는 3:1 이상을 후속 검수한다. 장식 구분선 `#dce3dd`와 필수 입력 경계 `#778a84`를 혼동하지 않는다.

한국어 시스템 글꼴을 사용하고 외부 폰트가 없더라도 읽을 수 있게 한다. 모바일 본문 16px, 데스크톱 본문 15~16px, 보조 정보 13px 이상을 기준으로 한다. 간격은 4·8·12·16·24·32·48px, 입력 모서리 8px·카드 12px·큰 패널 16px를 사용한다. 그림자는 모달의 구분 정도로 제한하고, 과도한 그라데이션·유리 효과·장식 대시보드를 피한다. 이는 확정 시안에서 추출한 측정값이 아니라 기존 문서의 디자인 제안값이다.

공통 탐색은 S0 대시보드와 S1~S7 단계 이름·번호·현재 위치다. 1024px 이상은 좌측 탐색과 표/본문·상세, 768~1023px는 drawer와 카드·한 열 상세, 520~767px와 320~519px는 카드·전체 화면 상세/폼·하단 주요 행동을 사용한다. 320/375/768/1024/1440px를 후속 검수 폭으로 삼는다. 동일 접근 모드·역할 안에서 허용된 기록 조회·승인·반려·교정·다운로드를 기기 간 동등하게 제공한다. 공개 방문자에게 금지된 쓰기·승인·권리 변경·다운로드를 모바일 동등성 때문에 노출하지 않는다.

모든 행동은 label과 상태 문구를 갖고 키보드 포커스를 표시한다. 최소 44×44px 조작 영역, 색과 텍스트를 함께 쓰는 배지, 안전 영역을 반영한 하단 여백, drawer/dialog 닫기·Escape·호출 위치 포커스 복원을 적용한다. 로딩·저장 중·빈 목록·오류·성공·보류를 각각 설계한다. 실제 개인정보·고객 기밀 대신 합성 예시를 사용하고, 실제 모집·현장 수행·계약 완료를 허위로 표현하지 않는다.

C-04 A로 현재 개발·시연은 합성 가공 사례와 이용 범위를 확인한 공개 연습자료를 사용한다. 실제 고객·비공개·식별 가능한 전문가 자료는 제외한다. 공개자료는 출처·이용 범위를 표시하고 합성으로 표시하지 않으며 권리를 자동 면제하지 않는다. 실제 파일럿 자료·권리·보존/삭제 조건은 도입 전 별도 결정한다.

C-05 A로 지정 운영책임자1명이 권리 증빙 확인·작업 검증·특정 승인 취소·재검토를 담당하고 각 판단의 대상 버전·사유·근거·담당자·일시를 별도 기록한다. 입력 자체가 이용 허락을 만들거나 독립 심사를 입증하지 않는다. 문제 시 영향받는 생성·추가 내보내기만 HOLD로 표시하고 보완 후 새 검토로 안내하며 과거 기록/스냅샷과 다른 유효 승인은 보존한다. 새 승인만으로 취소된 과거 승인과 그 패키지를 자동 복구하지 않는다. 개정 번호(record version), 실제 내용 식별값(material_hash), 검토 입력 식별값(input_hash)을 구분하고 번호만 증가한 일을 내용 변경이나 승인 취소 해제로 표시하지 않는다.

C-06 A로 첫 버전의 실제 AI 연동·외부 모델 전송·API 지출을 보류한다. 현재 초안은 수동/규칙 기반으로 표시하고 키·모델 설정만으로 호출하지 않는다. 자료 체계화·작업 정제의 선호 2개는 향후 도입 우선, 추가 AI 4개는 미채택 선택 제안으로 보존한다. C-01의 로컬 내부 운영과 권리·검토 검사를 거치는 로컬 JSON 다운로드를 유지한다.

C-07 B와 추가 권한 A로 해커톤 후속 공개는 합성 자료 조회·방문자별 분리 과제 실행/초기화만 허용하는 실제 동작 웹시연이다. 2026-10-24 21:00 KST(12:00 UTC)부터 새 공개 UI·API 접근을 서버에서 차단하고 DB는 보존한다. 등록·수정·권리 확인·승인/취소·재검토·회사 생성·다운로드는 운영자 보호 기능이며 공개 방문자의 직접 API 요청도 거절한다. 공개 실행/초기화는 방문자별 합성 시도에만 적용하고 운영자·다른 방문자 상태와 snapshot을 보존한다. 외부 전문가·구매자 계정을 추가하지 않는다. 호스팅·운영자 보호·방문자 분리 기술은 EPIC 13 착수 및 공개 전에 확인하며 로컬 기본 구축 시작을 막지 않는다. 별도 Build 요청 전에는 실제 구축·배포하지 않는다.

## 4. 독립 화면별 프롬프트

각 text 블록 하나를 디자인 도구에 독립적으로 전달할 수 있게 작성했다. 시안 제작을 이번에 수행했다는 뜻은 아니다. 실제 API·검증 조건의 구현 계약은 [FRD](frd.md)와 [TRD](trd.md)를 함께 따른다. C-06 A의 현재 화면은 수동/규칙 기반이며 선호 AI 2개와 추가 AI 4개는 향후 미채택 연동 명세로 구분한다. 실제 AI 기능을 별도 채택하기 전에는 실행 행동을 제공하지 않으며 현재 필수 범위를 늘리지 않는다.

## 5. 사용 안내와 확인 범위

위 블록은 Claude Design 또는 Google Stitch 같은 디자인 도구에 화면별로 하나씩 전달할 수 있다. 도구의 실제 사용 가능 여부·플랜은 사용할 때 확인한다. 이번 문서 검증에서는 도구 계정을 연결하거나 시안을 생성하지 않았다. 문구가 어색하면 해당 블록을 영어로 옮겨 재시도하되 화면 ID·게이트·모바일 동등 기능을 유지한다.

후속에 시안을 제작하면 `design/`에 화면 ID가 구별되는 이름으로 저장하거나 실제 캔버스 위치를 기록한다. 8개 블록과 8개 PRD 화면의 대응, 좁은/넓은 화면, 정상/보류 흐름을 확인한다. 시안이 없는 상태에서도 FRD·TRD의 문서 검증은 이어갈 수 있으며 시안 확인·제품의 최종 디자인 승인을 이미 받은 것처럼 보고하지 않는다.

이번 검증에서 수행한 것은 화면 누락·문서 대응·원문/초안/교정 구분·과제별 실행/초기화·내보내기 보류·모바일 동등 기능의 명세 점검이다. 실제 화면의 접근성·사용성·동작 검수는 별도다.
