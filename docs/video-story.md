# Frontier Lab Market — 3분 이내 소개 영상 스토리

- 상태: 확정 (영상 제작용 스토리; 실제 영상 제작·제품 Build는 별도)
- 변경 원칙: 이후 수정사항은 구축 과정에서 관련 문서에 함께 반영한다.
- 버전: 1.0 / 작성일: 2026-10-24 (Asia/Seoul)
- 참고 범위: 작성 시작 시점의 프로젝트 Markdown 9개와 작성 중 추가된 로컬 검수 보고서 1개, 총 10개. 문서별 반영 내용은 §6에 정리한다.
- 편집 길이: **2분 50초, 총 170초**. 인트로·전환·엔드카드를 모두 포함하며 최종 영상은 3분 미만으로 제작한다.
- 기본 형식: 한국어 내레이션 1명, 16:9 가로형, 1920×1080 기준의 소개 영상.
- 청중: 해커톤 심사위원과 AI 학습·평가 데이터 구매 담당자.
- 화면의 성격: **합성 사례를 이용한 개념 설명·구축 예정 흐름**. 현재 제품의 실제 동작 녹화나 구현 완료 보고로 제시하지 않는다.

## 1. 영상이 전달할 이야기

**“숙련자의 작은 판단을, 근거와 이용 범위가 연결된 AI 학습·평가 과제로 만든다.”**

표면 이상을 발견한 가공품에서 이야기를 시작한다. 바로 출하할지, 추가 점검을 요청할지 판단하는 장면으로 암묵지를 설명하고, 그 경험을 자료·전문가·검토·프로젝트와 연결하는 7단계를 보여준다. 마지막에는 가상회사의 작은 업무 과제로 같은 판단을 반복하는 모습을 통해 결과물을 구체화한다.

영상의 감정 흐름은 **궁금증 → 문제 이해 → 해결 과정 → 신뢰 → 구체적인 활용 → 다음 과제 제안**이다. 기능 수나 기술 용어를 나열하는 대신 하나의 판단 사례를 끝까지 따라간다.

## 3. 장면별 스토리보드와 내레이션

### 장면 01 — “이대로 출하해도 될까요?”

**시간:** 00:00–00:15 / 15초

**화면:** 합성 가공품의 표면을 가까이 보여주는 연출로 시작한다. 작은 이상 부위에 표시가 생기고, 화면 양쪽에 ‘바로 출하’와 ‘추가 점검’ 두 선택 카드가 나타난다. 특정 원인을 단정하는 문구는 넣지 않는다. 첫 장면부터 ‘합성 사례’ 표시를 유지한다.

**내레이션:**

> 가공품의 작은 표면 이상. 바로 출하할까요, 추가 점검이 필요할까요? 숙련자의 판단을 AI에게는 어떻게 전할 수 있을까요?

**핵심 자막:** “작은 단서, 다른 판단” / “바로 출하? 추가 점검?”

**연출:** 첫 2초는 현장 분위기를 전달하는 짧은 효과음과 화면으로 주의를 모은다. 이후 내레이션이 시작되고, 마지막 선택 카드를 다음 장면의 ‘판단’ 카드로 연결한다.

### 장면 02 — “경험에는 맥락이 있습니다”

**시간:** 00:15–00:30 / 15초

**화면:** 관찰 메모, 반복 연습, 교정 피드백이 차례로 쌓인다. 산업·공예·요리를 상징하는 간단한 도식을 보여준 뒤 ‘맥락 → 관측 단서 → 판단 → 결과’ 네 카드로 정리한다. 실제 고객·전문가의 사진이나 실적 대신 합성·개념 소재를 사용한다.

**내레이션:**

> 관찰과 반복, 교정으로 익힌 노하우. 산업현장부터 공예와 요리까지, 학습자료로 쓰려면 맥락과 근거, 이용 범위가 필요합니다.

**핵심 자막:** “관찰 · 반복 · 교정” / “맥락 + 근거 + 이용 범위”

**연출:** 종이 메모가 읽기 쉬운 정보 카드로 정리되는 움직임을 사용한다. AI가 자동으로 분석하거나 승인하는 효과는 넣지 않는다.

### 장면 03 — “경험을 판단 과제로 연결합니다”

**시간:** 00:30–00:48 / 18초

**화면:** Frontier Lab Market 타이틀이 나타난다. ‘도제 경험 → 전문가·사람 검토 → 학습·평가 데이터 → 가상회사 환경’이 하나의 선으로 이어진다. 화면 하단에 ‘제품 개념 · 구축 예정 흐름’을 표시한다.

**내레이션:**

> 프런티어 마켓은 도제 경험의 암묵지를 발굴하고, 전문가와 사람 검토를 거쳐 AI 학습·평가용 데이터와 가상회사 환경으로 연결하는 프로젝트입니다.

**핵심 자막:** “Frontier Lab Market” / “경험을, 근거 있는 학습·평가 과제로”

**연출:** 복잡한 모델 구조나 서버 도식 대신 사람·자료·과제의 연결만 보여준다. 브랜드명을 읽은 뒤 잠깐 쉬어 시청자가 이름을 기억하게 한다.

### 장면 04 — “7단계를 하나의 흐름으로”

**시간:** 00:48–01:13 / 25초

**화면:** 운영자 모드의 예정 화면을 카드 형태로 이어 보여준다. ‘운영자 업무 · 구축 예정’ 표시를 유지한다.

| 장면 안의 상대 시간 | 보여줄 내용 |
|---|---|
| 0~2초 | S0 대시보드: 전체 흐름과 다음 작업 |
| 2~5초 | S1 자료 수집: 원문과 출처 등록 |
| 5~8초 | S2 DB: 자료·전문가·작업의 연결 |
| 8~11초 | S3 전문가: 사람의 평가·승인 후 원시 작업 등록 |
| 11~14초 | S4 카탈로그: 관측 단서·판단·근거를 가진 주제 카드 |
| 14~17초 | S5 정제·검증: 원문·수동/규칙 초안·사람 교정본 구분 |
| 17~20초 | S6 FDE: 연결 프로젝트·범위·산출물·기업 AX 0원 |
| 20~23초 | S7 가상회사: 데이터 패키지와 업무 과제 |
| 23~25초 | 같은 운영자 모드의 모바일 카드 배치를 짧게 보여줌 |

**내레이션:**

> 자료를 모아 DB에 저장하고, 전문가를 평가한 뒤 원시 작업을 등록합니다. 이를 주제별 카탈로그로 묶어 정제하고 검증합니다. 기업 AX는 0원 원칙으로, FDE 프로젝트와 가상회사까지 연결합니다.

**핵심 자막:** “수집 → DB → 전문가 → 카탈로그 → 정제·검증 → 무료 AX·FDE → 가상회사”

**보조 자막:** “기업 AX 0원 원칙 · 구매자 대금·전문가 보수는 별도”

**연출:** 각 화면의 핵심 행동 하나만 확대한다. 작은 표 전체나 긴 JSON을 읽게 하지 않는다. 프로젝트 연결은 필수이지만, 이 장면을 현장 AX 완료나 컨설팅 실적으로 표현하지 않는다.

### 장면 05 — “누가, 무엇을, 어떤 목적으로 확인했나요?”

**시간:** 01:13–01:33 / 20초

**화면:** S5 운영자 모드에서 ‘전문가 승인’, ‘작업의 사람 검토’, ‘근거’, ‘카탈로그·프로젝트 연결’, ‘목적별 이용 범위’를 각각 구분한다. 별도의 합성 예시로 ‘평가 전용 자료 → 학습용 생성 요청 → 목적 불일치로 HOLD’를 보여준다. 운영자가 이유와 보완할 항목을 읽는 장면에서 마친다.

**내레이션:**

> 전문가 승인과 작업 검토는 별개입니다. 사람이 근거와 목적별 이용 범위를 확인하고, 조건이 부족하면 생성과 추가 내보내기를 보류하도록 설계했습니다.

**핵심 자막:** “사람의 검토” / “목적별 이용 범위” / “조건 부족 → HOLD”

**연출:** 승인은 청록, HOLD는 주의 색과 문구로 함께 표시한다. 인증서·공인 마크는 사용하지 않는다. 운영자 입력으로 원래 없던 권리가 생기는 표현도 넣지 않는다.

### 장면 06 — “가상회사에서 같은 판단을 반복합니다”

**시간:** 01:33–02:00 / 27초

**화면:** 장면 05의 HOLD 예시와 구분해, 사람 검토·이용 범위 등 생성 조건을 충족했다고 가정한 **별도 합성 가상회사 과제**로 전환한다. ‘합성 과제 · 공개 체험 예정 흐름’ 표시를 유지한다. 이 장면에는 운영자 전용 생성·승인·다운로드 버튼을 노출하지 않는다.

| 장면 안의 상대 시간 | 행동과 결과 |
|---|---|
| 0~4초 | 합성 작업지시와 표면 이상 관측 정보 확인 |
| 4~9초 | 검사 전 ‘출하’ 시도 → ‘검사 필요’ 사유와 함께 차단 |
| 9~15초 | ‘검사 요청’ → 준비된 합성 검사 결과 확인 |
| 15~20초 | 검사 완료 뒤 ‘출하’ 재시도 → 허용되는 결과 표시 |
| 20~24초 | 선택 과제 ‘초기화’ → 새 시도를 초기 상태로 시작 |
| 24~27초 | ‘나의 시도’ 표시. 다른 방문자·운영자의 상태와 고정 자료는 보존됨을 도식으로 표현 |

**내레이션:**

> 가상회사에서는 판단이 업무 과제가 됩니다. 합성 사례에서 점검 없이 출하하면 차단되고, 점검을 마친 뒤 다시 시도하면 허용되는 흐름입니다. 초기화해 같은 과제를 반복할 수 있도록 계획했습니다.

**핵심 자막:** “검사 전 출하 → 차단” / “검사 후 출하 → 허용” / “초기화 → 새 시도”

**연출:** 행동과 결과가 같은 화면에서 보이게 한다. 실제 설비 가동·제어로 연결하지 않으며, 규칙 충족 결과를 실제 숙련도나 AI 모델 성능 점수로 표시하지 않는다.

### 장면 07 — “구매자가 검토할 수 있는 결과물”

**시간:** 02:00–02:20 / 20초

**화면:** 운영자 모드의 패키지 미리보기로 돌아온다. ‘업무 자료 / 과제 / 기대 답안 / 평가 기준 / 출처·이용 범위’를 보여준 뒤, ‘샘플 검토 의견 / 파일럿 조건 논의 / 필요 주제 추천’ 세 카드가 보완 작업으로 이어지는 도식을 보여준다. AI 연구팀·데이터 구매자는 목표 고객으로 표시한다.

**내레이션:**

> 업무 자료와 과제, 기대 답안과 평가 기준을 묶은 데이터 패키지. 구매자의 샘플 검토, 파일럿 조건 논의, 필요 주제 추천으로 다음 과제를 구체화합니다.

**핵심 자막:** “AI 학습·평가용 데이터와 업무 환경” / “샘플 검토 · 파일럿 조건 · 주제 추천”

**연출:** 계약 완료·결제 성공·고객사 로고 대신 의견 기록과 피드백 연결을 보여준다. 공개 방문자가 패키지를 생성하거나 다운로드하는 흐름으로 연결하지 않는다.

### 장면 08 — “현재의 출발점”

**시간:** 02:20–02:35 / 15초

**화면:** PRD·Design·FRD·TRD·Plan 문서 카드에 ‘확정’을 표시한다. 이어서 ‘로컬 검수 보고 / 화면·공개 검수는 별도’, ‘첫 버전: 수동·규칙 기반’, ‘실제 AI 연동: 보류’를 차례로 보여준다. 개발계획의 체크 상태를 제품 완성 표시로 바꾸지 않는다.

**내레이션:**

> 문서와 개발계획은 확정했습니다. 검수 범위를 구분하며, 첫 버전은 수동·규칙 기반입니다. 실제 AI 연동은 보류합니다.

**핵심 자막:** “문서 확정 · 검수 범위 구분” / “수동·규칙 기반 · 실제 AI 보류”

**연출:** 녹색 완료 표시는 문서 카드에만 적용한다. 추가된 [로컬 검수 보고서](acceptance-local.md)는 테스트·GET 확인 결과와 브라우저·공개 검수의 미실행을 구분한다. 이를 전체 제품 검수나 배포 완료로 확대하지 않는다. 실제 AI 응답 효과는 넣지 않으며 AI 외부 전송·API 지출 보류도 유지한다.

**핵심 자막:** “현장의 경험을, 근거 있는 판단으로.” / “AI가 배워야 할 과제를 제안해 주세요”

**엔드카드:** `Frontier Lab Market` / `필요 주제 추천 · 샘플 검토 · 파일럿 조건 논의`

**연출:** 현재 확보된 접속 링크를 전제로 하지 않고 브랜드와 대화 주제로 마무리한다. 배경음은 엔드카드 안에서 자연스럽게 끝내며 별도 아웃트로를 추가하지 않는다.

## 4. 제작·편집 기준

- **화면 톤:** 크림 배경 `#f7f5ef`, 흰 카드 `#ffffff`, 남색 `#172c3a`, 청록 `#1e6b60`을 기본으로 한다. 문서의 차분한 작업 공간 분위기를 유지한다.
- **정보량:** 한 번에 핵심 문구 하나를 강조한다. 자막은 최대 두 줄로 나누고 상태는 색과 ‘합성·검토 대기·승인·HOLD’ 문구를 함께 쓴다.
- **화면 자료:** 본 스토리에 실제 앱 녹화는 첨부하지 않는다. 먼저 개념 카드·도식을 제작할 수 있으며, 실제 화면 녹화로 교체할 때에는 해당 화면의 검수 후 확보한 자료를 사용한다. 로컬 테스트·GET 기록만으로 브라우저 동작을 검수했다고 표시하지 않는다. 소개 영상은 해커톤의 실제 작동 페이지나 제품 검수를 대신하지 않는다.
- **역할 표시:** 장면 04·05·07은 운영자 업무, 장면 06은 공개 체험 범위의 예정 흐름이다. 공개 체험은 합성 자료 조회·방문자별 과제 실행/초기화에 한정한다. 화면 전환 시 역할 표시도 함께 바꾼다.
- **소재:** 가공품·회사·인물·작업지시·검사 결과는 합성 예시로 구성한다. 공개 연습자료를 사용할 경우 이용 범위를 확인하고 합성 자료와 구분한다. 공개 시연용 화면에는 합성 자료만 사용한다.
- **음성·음악:** 설명이 또렷한 한국어 화자 한 명을 기본으로 하고, 배경음은 사용권을 확인한 잔잔한 곡을 낮게 깐다. AI는 ‘에이아이’, AX는 ‘에이엑스’, DB는 ‘디비’, FDE는 ‘에프디이’로 읽는다.
- **주장의 범위:** 본 영상은 확정 설계와 목표를 설명한다. 실제 고객 확보·매출·현장 AX 성과·모델 학습/성능 향상·공인 인증·권리 취득을 실적으로 제시하지 않는다. 기업 AX 0원은 데이터 구매 대금·전문가 보수까지 무료라는 의미로 확대하지 않는다.
- **시점 관리:** 장면 08은 작성일의 문서와 추가된 로컬 검수 기록을 기준으로 한다. 이 영상 스토리 작성에서는 테스트·서버·브라우저를 실행하거나 다른 작업자의 검수 결과를 재실행하지 않았다. 이후 구축 상태가 달라지면 확인된 결과에 맞춰 내레이션과 자막을 함께 갱신한다. 공개 웹 시연의 종료 정책은 **2026-10-24 21:00 KST(12:00 UTC)**이며 이후 새 공개 UI/API 접근을 차단하고 DB를 보존한다. 해당 시각 뒤 새 공개 배포·재공개를 시작하는 안내를 넣지 않는다. 이는 공개 웹 운영 정책이며 영상 파일의 상영 종료 시각을 뜻하지 않는다.

로컬 검수 보고서의 ‘브라우저 미실행’은 그 보고서 작성 당시 기록이다. 작성 중 담당자는 이후 320px·768px에서 S0~S7 로딩과 가로 넘침을 추가 확인했다고 보고했다. 전체 흐름의 클릭 조작·실기기 키보드/safe-area·공개 시연 검수와는 구분한다. 장면 08은 ‘화면·공개 검수를 구분한다’는 표현을 유지하고, 촬영 시점의 최신 확인 범위를 반영한다.

## 5. 3분 이내로 완성하는 시간 기준

편집표의 배정 시간은 총 **170초**다. 실제 녹음·편집 시간의 측정 결과는 아니며, 제작 시 장면별 구간 안에 내레이션과 쉼을 맞춘다. 170초에 전환과 엔드카드가 이미 포함되어 있다.

1. 장면별 내레이션을 녹음하고 배정 시간을 확인한다. 브랜드명·영문 약어는 §4의 읽는 방식으로 녹음한다.
2. 목소리를 과하게 빠르게 만들기보다 장면 02의 분야 예시나 장면 07의 연결 문장을 먼저 간결하게 줄인다. 사람 검토·AI 보류·현재 상태 표시는 유지한다.
3. 음악의 앞뒤 여백과 마지막 정지 화면을 포함해 **2분 50초를 기본 목표**로 맞춘다. 편집 중 조정 여유는 최대 9초로 두고 **최종 파일은 2분 59초 이하**로 확인한다.
4. 최종 재생에서 합성/예정 화면 표시, 운영자·공개 역할, 자막 가독성과 음성의 끝부분이 잘리지 않는지 확인한다.
