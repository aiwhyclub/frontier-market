## 1. 제품 경험과 청중

산업현장 또는 다른 분야에서 도제 경험으로 얻는 암묵지를 자료→전문가→과제→검증→가상회사로 연결한다. 발표·대회 심사위원에게는 단계별 가치가 보이고, 실제 Lab·평가 데이터 구매자에게는 샘플·근거·이용 범위가 보이게 한다. 하나의 반응형 웹에서 S0 대시보드와 S1~S7의 모든 업무를 제공한다.

모든 화면에서 합성/직접 입력/공개 수집, 수동/규칙 기반 초안/사람 검토, 목적별 이용 범위를 구별한다. 실제 AI 표시는 향후 미채택 연동의 명세로 구분하며 현재 규칙 초안을 실제 AI 결과처럼 표시하지 않는다. DB 저장·데모 승인과 실제 모집·현장 수행·권리 확보·사업성 입증은 구분한다. 화면 ID는 [FRD](frd.md)와 프롬프트의 추적 기준이며 별도 화면을 추가한 것이 아니다.

C-04 A로 현재 개발·시연은 합성 가공 사례와 이용 범위를 확인한 공개 연습자료만 사용한다. 실제 고객·비공개·식별 가능한 전문가 자료를 예시로 넣지 않는다. 공개자료는 실제 출처와 이용 범위 상태를 표시하고 합성 배지로 바꾸지 않는다. 공개·발굴용 참조의 권리 자동 면제는 없으며 미확인은 HOLD로 표시한다. 실제 파일럿 자료·공급자·권리·보존/삭제 세부조건은 도입 전 별도 결정한다.

C-06 A로 첫 버전의 실제 AI 연동·외부 모델 전송·API 지출은 보류하고 수동/규칙 기반으로 진행한다. 키·모델 설정만으로 호출하지 않는다. 자료 체계화·작업 정제 2개는 향후 도입 우선, 추가 AI 4개는 선택 제안으로 보존한다. C-01의 같은 컴퓨터에서 사용하는 로컬 내부 도구와 로컬 JSON 내보내기의 권리·검토 검사를 유지한다.

C-07 B와 추가 권한 A로 해커톤 후속 확장은 합성 자료의 조회와 과제 실행/초기화만 허용하는 실제 동작 공개 웹시연이다. 공개 기한은 2026-10-24 21:00 KST(12:00 UTC)이며 이 시각부터 새로운 공개 UI·API 접근을 서버에서 차단하고 저장 DB는 보존한다. 등록·수정·권리 확인·승인/취소·재검토·회사 생성·다운로드는 운영자 보호 기능이다. 공개 실행/초기화는 방문자별로 분리된 합성 시도에만 적용하며 운영자·다른 방문자의 상태와 고정 스냅샷을 바꾸지 않는다. 외부 전문가·구매자 계정은 추가하지 않는다. 호스팅·운영자 보호·방문자 분리의 기술수단은 EPIC 13 착수 및 공개 전 준비사항이며 로컬 기본 구축 시작을 막지 않는다. 별도 Build 요청 전에는 실제 구축·배포하지 않는다. 공개 범위 선택은 구현 완료나 시안 제작 완료를 뜻하지 않는다.

주 사용 기기는 **Web+Mobile 모두**다. 동일 접근 모드·역할 안에서 허용된 기능은 기기 간에 동등하게 제공하며 좁은 폭의 배치를 먼저 정하고 넓은 폭으로 확장하는 방식을 구현 제안으로 둔다. 공개 방문자에게 금지된 등록·수정·승인·권리 변경 등을 모바일 동등성이라는 이유로 노출하지 않는다. 사용자가 모바일만 우선한다고 확정한 것은 아니다.

## 4. 시각 체계

| 역할 | 디자인 값 |
|---|---|
| 탐색 남색 | #172c3a |
| 크림 배경·흰 표면 | #f7f5ef / #ffffff |
| 본문·보조 문자 | #1d2c2b / #5c6765 |
| 주요 행동 청록 | #1e6b60 |
| 주의 주황 | #9b5627 (일반 텍스트 대비 확인 대상) |
| 오류 | #a63b36 |
| 장식 구분선·필수 입력 경계 | #dce3dd / #778a84 (서로 용도를 구분) |
| 간격 | 4·8·12·16·24·32·48px |
| 모서리 | 입력 8px, 카드 12px, 큰 패널 16px |

위 색·간격·글자 값은 실제 제품 시안을 측정한 값이 아니라 기존 무드를 유지하는 구축 제안값이다. 색상 쌍의 대비를 계산할 수 있어도 실제 화면의 시각·사용성 검수가 끝난 것은 아니다. 한국어 시스템 글꼴을 기본으로 쓰고 외부 폰트 다운로드를 필수로 하지 않는다. 본문은 모바일 16px·데스크톱 15~16px, 보조 정보는 13px 이상을 기준으로 한다. 핵심 상태는 작은 저대비 문자에 의존하지 않는다. 일반 텍스트 대비 4.5:1, 큰 텍스트·주요 UI 경계 3:1 이상을 후속 검수 목표로 삼고 실제 색 조합으로 확인한다. 기준은 [W3C 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 참고하며 현재 제품의 접근성 인증·실검수를 뜻하지 않는다. 필수 입력 경계·포커스는 장식 구분선과 구분하며 [W3C 비텍스트 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)을 기준으로 검수한다. 의미는 색과 함께 텍스트·아이콘으로 전달한다.

## 5. 반응형 Web+Mobile

| 상호 배타적 구간 | 배치·상호작용 설계 |
|---|---|
| 1024px 이상 | 좌측 탐색·표+상세. 1440px에서는 넓은 대시보드, 1024px 부근은 상세 패널 접기 |
| 768~1023px | 메뉴 drawer·한 열 본문·카드 목록, 상세는 전체 화면 또는 한 열 |
| 520~767px | 메뉴 drawer·카드·전체 화면 상세/폼, 입력 한 열·하단 주요 행동 |
| 320~519px | 같은 핵심 기능을 한 열·전체 화면 폼으로 제공, 320/375px에서 넘침 점검 |

데스크톱의 데이터 표·우측 상세는 모바일에서 항목별 카드·전체 화면 상세로 바꾼다. 표의 모든 열을 작게 축소하지 않는다. 핵심 입력과 결과가 잘리지 않게 하고, 긴 JSON·원문만 내부 스크롤을 허용한다. 페이지 전체 가로 넘침을 피한다.

모바일 주요 행동은 하단 action 영역에 두되 본문에 높이만큼 여백을 남긴다. `env(safe-area-inset-bottom)`을 반영하고 가상 키보드가 열린 상태에서도 현재 필드·오류·저장 행동에 접근하게 한다. drawer와 전체 화면 폼은 닫기·뒤로가기·Escape를 제공하고, drawer는 바깥 영역 선택으로도 닫는다. 닫은 뒤 호출 버튼으로 포커스를 돌리고 폼/상세는 위치를 복원한다. 터치 대상은 44×44px 이상을 목표로 한다. 호버에만 있는 기능을 만들지 않는다.

### 5.1 모바일 카드의 정보 우선순위

| 단계 | 카드·상세의 필수 정보/행동 |
|---|---|
| 자료 | 제목·출처·수집/권리 상태·상세·이용 범위 수정 |
| 지식 DB | 유형·분야·연결 대상·상태·상세 탐색 |
| 전문가 | 이름·분야·승인 상태·평가→업로드·제공 동의 확인 |
| 카탈로그 | 분야·판단 역량·원천 연결·샘플/파일럿/주제 의견 |
| 정제 작업 | 원문/초안 탭·수동/규칙 생성 방식·교정 저장·사람 검증 |
| FDE | 단계별 세로 목록·범위·무료 AX·선택 F6.5 채택 시 가정 손익 구분 |
| 가상회사 | 회사/과제 선택·현재 권리/검토·실행 상태·3행동·snapshot 내보내기 |

긴 근거·JSON은 접었다 펼칠 수 있게 하고 동일 접근 모드·역할에 허용된 핵심 행동과 승인/보류 사유는 기기 크기를 이유로 숨기지 않는다. 운영자 전용 폼과 공개 쓰기 금지는 유지한다.

### 5.2 텍스트 와이어프레임

아래는 후속 구축을 위한 배치 설명이며 실제 이미지 시안·구현 화면이 아니다.

데스크톱:

```text
좌측 탐색      │ 상단: 현재 위치 · 검색 · 상태
대시보드       │ 단계별 요약 지표 · 다음 작업
1 자료 / 2 DB  │ 목록·필터            │ 선택 항목 상세
3 전문가      │ 카드/표              │ 근거·이용 범위
4 카탈로그    │ 주요 작업 영역        │ AI/사람 검토 이력
5 검증 / 6 FDE│ 보완 안내·주요 행동    │ 관련 자료
7 가상회사    │ 샘플·파일럿·주제 의견
```

모바일:

```text
메뉴 · 현재 단계 · 상태
검색 / 상태 필터
핵심 정보 카드 → 전체 화면 상세
원문 / 초안 · 교정/검토 행동
보류 이유 → 이용 범위 확인 폼
샘플·파일럿·주제 의견
하단 주요 행동 + safe-area 여백
```

## 6. 핵심 작업 패턴

### 6.1 자료·전문가·카탈로그

자료 폼은 URL 가져오기와 본문 입력을 분리한다. 공개 접근이 학습/배포 허용을 뜻하지 않음을 출처 근처에 표시한다. 비공개 클라우드 연결을 지원하는 것처럼 표현하지 않는다. 전문가 원시 업로드는 승인 후 가능하며 카탈로그 없이 임시 작업을 저장할 수 있다. 4단계에서 자료·전문가·업로드 작업을 과제로 연결한다. 발굴 후보는 도제 경험 기원·비표준/문서화 공백·현장 기본 필요성과 오판 비용·숙련자/초보자 차이·결과 검증 가능성·Lab 평가 역량 연결의 6축을 근거와 함께 기록한다. 우선순위 점수는 가설이며 전문성 보증이 아니다. 텍스트 외 media_refs는 출처·유형·시점/설명 메타데이터만 연결하고 자동 분석은 후속으로 둔다.

후보 상태는 지원/보완/승인/반려로 표현한다. C-02 A에 따라 평가 폼에 도제 경험의 구체성·관측 단서 설명·판단/예외 설명·결과/근거 연결의 4축을 각0~3점으로 입력하고 동일25%·참고합계0~12를 표시한다. 0=현재 자료로 확인 불가, 1=개략적 설명, 2=구체 사례로 설명, 3=사례·근거·한계까지 설명이라는 도움말을 둔다. 지정 운영책임자1명의 최종 판정·사유·평가자·일시와 4축 점수는 필수다. 미입력과0점을 구분하고 합계로 자동 승인하지 않는다. 승인 전 업로드 버튼에는 필요한 평가 행동을 안내하고 서버도 차단하도록 설계한다. 승인 후에는 원시 작업·근거·선택적 출처를 업로드할 수 있고 카탈로그 미연결 상태를 표시한다. 사람의 로컬 판정을 실제 자격 인증이나 독립 심사로 확대하지 않는다.

자료 상세와 DB에서 원문, 정리 결과, 연결 자료/전문가/작업, 현재 상태를 읽을 수 있다. 관련 기록을 열어도 검색어·필터·목록 위치를 복원한다. 카탈로그 편집에서는 원천 자료·전문가·원시 작업을 선택하고 변경된 연결을 저장한다. 비어 있는 연결은 미연결로 표시하고 정제·생성 전에 필요한 보완 항목을 안내한다.

S1 자료 상세와 S5 작업 상세에 운영자 전용 ‘원문·근거 개정’을 제공한다. 현재 내용을 편집 폼으로 복사하고 개정 사유·담당자·일시와 함께 새 버전을 저장한다. 과거 원문·근거·검토 이력·스냅샷은 덮어쓰지 않으며 변경된 검토 입력은 재검토로 안내한다. 정제 초안 채택이 원문을 수정하는 동작은 아니다.

S4 편집 폼에서 발굴 6축을 각각 근거·미확인과 함께 입력/수정하고 탐색 우선순위를 비교한다. 선택 매체 참조는 출처·형식·시점/설명 메타데이터를 입력·수정하며 자동 분석은 수행하지 않는다. 자료의 발굴 맥락을 읽는 것과 카탈로그에 이 판단을 저장하는 것을 구별한다.

### 6.2 정제·교정·채택·검증

데스크톱은 원문과 정제 결과를 나란히, 모바일은 **원문 / 생성 초안 / 채택·교정본** 탭으로 보여준다. 세 탭에서 같은 작업·입력 버전을 확인하고 미저장 교정 내용을 보존한다. 탭은 키보드로 이동할 수 있고 현재 선택을 읽을 수 있게 한다. 도제 학습 맥락→관측 단서→초보자 차이→판단·예외→결과 확인을 연결한다. 감각 단서가 없는 자료를 물리 숙련 전체의 재현으로 표시하지 않는다.

원문은 정제 결과로 덮어쓰지 않는다. C-06 A의 현재 체계화·정제 초안에는 수동/규칙 기반, 생성 시각, 입력 버전/해시, 대기/성공/실패와 채택 여부를 표시한다. 실제 AI 도입 우선 2개와 추가 제안 4개는 향후 미채택 연동이며 현재 실행 버튼이나 성공 표시로 제공하지 않는다. 향후 별도 채택 시 실제 AI의 모델·생성 시각·입력 버전/해시와 규칙 결과를 구분한다. 초안이 도착해도 현재 기록을 자동 수정하지 않고 ‘이 초안 채택’으로 편집 중인 교정본에 반영한다. 사람은 교정본을 수정한 뒤 ‘교정본 저장’으로 새 검토 대상 버전을 만든다. **초안 채택·교정 저장·검증 승인은 별개의 행동**이다. 교정한 버전은 검토 대기로 표시하고 원본·이전 생성 결과·과거 검증은 보존한다.

요청 중 입력이 바뀌거나 늦은 결과가 도착하면 이전 입력의 초안임을 표시하고 현재 교정본에 자동 적용하지 않는다. 현재 초안은 처음부터 수동/규칙 기반이라고 표시하고 처리 실패에는 입력을 보존해 수동 교정으로 계속하게 한다. 향후 실제 AI를 별도 채택하면 호출 실패와 규칙 기반 대체 결과를 각각 알려 명시적으로 대체 초안을 사용하게 한다. 저장 충돌은 최신 버전 확인·입력 복구를 안내하며 조용히 덮어쓰지 않는다.

사람 검토에는 승인/반려·결과·근거·검토자·일시·확인한 버전이 필요하다. C-05 A로 지정 운영책임자1명이 작업 검증·재검토를 맡으며 권리 확인과 별도 기록한다. 검토 입력/해시가 바뀌면 다시 확인하고 기존 승인 배지를 그대로 적용하지 않는다. 상태 저장으로 기록 번호만 증가하고 검토 입력이 같으면 취소되지 않은 기존 유효 판정을 유지한다. 해시가 같다는 이유로 승인 취소나 현재 권리 HOLD를 해제하지 않는다.

같은 운영책임자가 과거 승인 취소의 대상 승인 기록·검토 버전·사유·근거·담당자·일시를 확인·저장한다. 취소 영향이 있는 현재 작업의 생성·패키지 추가 내보내기는 HOLD로 표시하고 보완 후 새 검토로 안내한다. 원래 승인·스냅샷과 다른 유효 승인은 보존하며 새 승인만으로 과거 취소/패키지가 자동 복구됐다고 표시하지 않는다. 모바일에서도 취소 대상과 사유를 생략하지 않는다. 같은 사람의 검토를 독립 심사로 표시하지 않는다.

개정 번호(record version), 실제 내용 식별값(material_hash), 사람 검토 입력 식별값(input_hash)을 상세에서 구분한다. 권리는 실제 대상 내용에, 사람 판정은 검토 입력과 특정 승인 기록에 연결한다. 상태 저장으로 개정 번호만 증가한 경우와 실제 내용·검토 입력이 변경된 경우를 같은 재승인 사유로 표시하지 않는다.

### 6.3 이용 범위 확인·수정

학습 생성은 작업·연결 출처·전문가 제공 범위의 공통 허용 목적을 확인한다. 학습/평가 purpose와 allow_derivatives(파생 제작)·allow_distribution(외부 제공)을 별도 표시한다. 자료·전문가·작업 상세의 공통 ‘이용 범위 확인·수정’에서 대상/버전·제공자·허용 목적·파생 제작·외부 제공 범위·근거·확인자·일시·기간·제한·현재 확인 상태를 입력한다. 각 입력은 실제 확인 내용을 기록하는 것이며 체크만으로 이용 허락이 생기는 것으로 표시하지 않는다. 저장한 뒤 영향받는 현재 작업·패키지의 보완 상태와 필요한 재검토를 보여준다. 모바일에서도 같은 전체 화면 폼을 제공한다. 권리 미확인·만료·제한·검증 대기는 별도 사유로 표시하고 해당 폼으로 돌아가게 한다. AI가 이를 승인하거나 해제하지 않는다.

C-05 A로 지정 운영책임자1명이 원 권리자·제공자의 허용 근거를 확인하고 대상 버전·확인 사유·근거·담당자·일시를 기록한다. 운영자 입력 자체가 허락을 만들지 않으며 합성 동의는 연습용 예시로 표시한다. 권리 미확인·만료·철회와 작업 검증 취소의 보류 사유를 구분하고 영향받는 생성/추가 내보내기를 HOLD로 안내한다. C-04의 실자료 도입 제한과 보존/삭제 별도 결정은 유지한다.

### 6.4 FDE 프로젝트

FDE는 기업 무료 AX와 구매자 매출/가정 비용을 분리한다. 기업 AX는 0원 고정임을 명시하고 프로젝트 범위·담당·단계·연결 작업·산출물·메모·현장 결과를 입력한다. 구매자 대금·전문가 보수와 기업 무료 AX의 구분을 유지한다. 가정 손익 자동 계산은 FRD F6.5의 선택 제안이며 기본 화면의 필수로 확정하지 않는다. 채택할 경우 금액은 통화·단위를 함께 표시하고 가정 가격 0의 이익률은 ‘계산 불가’로 표시한다. 현장 실제 수행과 계획·합성 상태를 명시한다.

### 6.5 가상회사 데이터·과제 실행·내보내기

가상회사에서는 회사/패키지와 그 안의 과제를 구분한다. 과제가 하나이면 이름·버전을 명시하고, 여러 과제가 있으면 실행할 과제를 먼저 선택한다. 학습 데이터·업무 문서·평가 자료·미니환경을 구분하고 생성 당시 고정 패키지와 현재 검토/실행 상태를 나눠 보여준다.

생성 폼은 C-03 A에 따라 FDE 프로젝트 선택을 필수로 제공하고 작업·카탈로그 관계 일치를 확인한다. 프로젝트 진행 단계는 사실대로 표시하되 현장 완료·단계 자체로 생성을 차단하지 않는다. 전문가·사람 검증·근거·목적별 이용 범위의 현재 조건은 계속 검사한다. 프로젝트 누락/관계 불일치는 S6 등록·연결 폼으로, 다른 보류는 담당 평가·검증·이용 범위 폼으로 직접 안내한다. 검증 대상에 변경이 있으면 ‘새 버전 재검토’로 안내하며 이전 승인을 자동 승계하지 않는다. 생성 성공을 현장 완료나 납품 승인으로 표시하지 않는다.

선택 과제의 현재 업무 상태와 실행 시도를 보면서 ‘검사 요청 / 보류 / 출하 승인’을 실행한다. 검사 전 출하는 차단 사유를 표시한다. 실행 결과·허용 행동·규칙 시연 점수·과제별 이력을 읽을 수 있게 한다. ‘이 과제 환경 초기화’는 선택 과제의 새 시도만 시작하며 다른 과제·고정 패키지·과거 실행 이력을 삭제하지 않는다. 진행 중 반복 클릭을 막고 동시 변경이면 최신 상태를 다시 불러오도록 안내한다. 초기화 전에도 변경 대상을 버튼 근처에 명시한다.

JSON 다운로드는 C-07 추가 권한 A에 따라 운영자 보호 기능이며 공개 방문자에게 버튼이나 직접 API로 허용하지 않는다. 운영자 다운로드 전에도 서버가 현재 권리·검토 조건을 다시 확인한다. 허용이면 생성 당시 버전·목적·고정 JSON과 현재 검토 알림을 구별해 로컬 파일로 내보낸다. 보류이면 다운로드 링크 대신 사유·관련 대상/버전·보완 폼 바로가기를 제공한다. 단순 원문 개정은 새 버전을 재검토하고 기존 패키지의 본문을 바꾸지 않는다. 기존 패키지에 적용되는 권리·과거 검증이 철회/만료/미확인으로 바뀌면 감사용 보존은 유지하되 추가 내보내기는 HOLD로 표시한다. 이미 받은 파일을 회수한 것으로 표현하지 않는다. 공통 검사→보류/해제 미니환경은 실제 산업 시뮬레이터나 모델 성능 측정이 아니다.

### 6.6 구매자 후속 의견

샘플 검토(sample_review), 파일럿 조건(pilot), 필요 주제(topic) 세 버튼을 카탈로그·가상회사·대시보드에서 찾을 수 있게 한다. 관련 대상·의견·희망 조건을 기록하고 유형별 저장 목록과 이후 연결할 보완 작업을 읽을 수 있게 한다. 카탈로그가 아직 없으면 ‘신규 주제 제안’을 제공하고 topic의 카탈로그 연결은 선택 사항으로 두어 빈 DB에서도 저장하게 한다. 나중에 주제·카탈로그를 만들면 기존 의견과 연결할 수 있게 한다. 기존 대상이 없는 다른 의견도 없는 대상을 있는 것처럼 표시하지 않는다. 외부 발송·주문·결제가 발생하는 것으로 표현하지 않는다.

S0/S4/S7의 운영자 전용 의견 상세에서 내용·현재 처리 상태·연결된 보완 대상을 확인하고 처리 상태와 자료·카탈로그·정제·FDE·회사 보완 대상 연결을 수정·저장한다. 처리 상태는 미지정 또는 1~80자의 처리 메모이며 새 업무 단계나 자동 진행을 만들지 않는다. 저장 성공/실패를 구분하고 재조회한 상태·연결이 저장값과 일치해야 한다. 공개 방문자는 합성 의견을 읽을 수 있지만 의견 등록·상태 수정·연결 변경은 할 수 없으며 직접 API도 거절한다.

## 7. 접근성·오류·후속 검수 계획

C-07 B 공개 시연에는 종료 시각·합성 예시·조회/과제 체험 전용 안내를 표시하고 기한이 끝나면 공개 화면을 비공개 상태로 전환한다. 공개 방문자는 등록·편집·권리/승인·회사 생성·다운로드 폼을 조작할 수 없으며 직접 API 요청도 서버가 거절한다. 과제 실행/초기화는 방문자별 합성 시도에만 적용하고 다른 방문자·운영자 상태와 snapshot을 보존한다. 버튼을 숨기는 것만으로 완료하지 않으며 2026-10-24 21:00 KST부터 새 공개 UI 요청과 직접 API 요청을 서버에서 차단한다. 종료는 공개 접근의 중단이며 DB·원문·검토/취소 이력·스냅샷 삭제나 초기화가 아니다. 호스팅·운영자 보호·방문자 분리 기술은 EPIC 13 착수 및 공개 전에 확인하며 로컬 기본 구축의 선행 조건으로 삼지 않는다. 기존 내부 운영 역할을 공개 방문자에게 자동 부여하지 않는다.

명시적 label·제목 계층·본문 바로가기·키보드 포커스·dialog 포커스 복원·aria-live 상태 안내를 설계한다. 저장 중 중복 행동을 막고 실패 시 입력을 보존한다. 빈 상태에는 첫 등록 행동, 권리 보류에는 필요한 확인, 규칙 처리 실패에는 수동 교정으로 계속하기를 제공한다. 오류에는 키·원시 traceback을 노출하지 않는다.

후속 구축 후 320/375/768/1024/1440px에서 동일 접근 모드·역할 안의 허용된 핵심 흐름을 동등하게 검수한다. 운영자의 URL/텍스트 등록·원문/근거 개정, 전문가 평가·업로드, 발굴 6축·매체 참조·카탈로그 연결, 정제·사람 확인, 무료 AX 프로젝트, 생성 차단/성공, 환경 실행/초기화, 다운로드, 세 의견의 상태·보완 대상 수정이 대상이다. 공개 방문자는 합성 조회·분리 과제 실행/초기화만 검수한다. 이는 **검수 계획이며 실제 통과 보고가 아니다**.

화면별 제작 기준은 [디자인 프롬프트 8개](design-prompt.md)를 사용한다. 실제 시안 제작·이미지 확인·시각/사용성 검수는 이번 문서 검증에서 수행하지 않았다. 후속 제작 때 S0~S7 대응과 좁은/넓은 화면을 확인하고, 제품 기준을 최종 승인받은 사실과 문서 수정 완료를 구분해 기록한다.
