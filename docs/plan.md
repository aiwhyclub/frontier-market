`세팅 → 영구 구조·합성 시드 → 자료 → 전문가 평가/승인·무카탈로그 업로드 → 카탈로그 → 권리 기록·과거 읽기 → 정제·교정·최신 사람 검증 → 무료 AX 프로젝트 → 현재 게이트·가상회사·과제 실행/reset·export → 세 의견·운영 동선` 순서입니다.

- [ ] STORY 13.1: 해커톤 공개 시연의 권한·운영·공개 종료 조건 확정 (완료 확인: 공개 조회·방문자별 합성 과제 run/reset과 운영자 전용 등록·수정·권리 확인·승인·회사 생성·export 범위를 기록한다. 계정 기능 추가 없이 운영자 보호를 제공할 호스팅/서버 인증 경계, 방문자 세션 발급/검증 방식, 호스팅·비용·합성 전용 영구 DB/백업·저장소/배포 수단·운영 책임을 구체화한다. 공개 종료 2026-10-24 21:00 Asia/Seoul(12:00 UTC)의 서버 차단 수단과 이후 운영자 비공개 접근 경로를 정한다. 제공자·비용·권한 등 미확인 항목이 있으면 이 STORY를 미완료로 유지하고 공개 준비/실행을 진행하지 않는다. 별도 Build와 실행 조건 확인 전 가입·지출·push·실제 배포를 진행하지 않는다.)
- [ ] STORY 13.2: 실제 동작하는 시연 서버·영구 저장·공개 차단 수단 준비 (완료 확인: Flask와 전용 WSGI 서버·TLS/접근 제한·비밀 설정·합성 전용 영구 SQLite/백업 경로를 확인한다. 7단계 저장·검증·가상회사·권리 검사 후 운영자 JSON 내보내기는 실제 API/영구 DB와 연결한다. TRD의 공개 prefix 조회/run/reset API와 인증된 운영자 API를 분리하고 공개 조회의 현재 권리/HOLD 검사도 적용한다. 공개 모드의 /api/demo 외 GET을 포함한 운영자 경로는 인증을 기본으로 하며 TRD의 nonce·서명·만료 쿠키와 CSRF 보호를 적용한다. company_runs의 demo_session_ref별 현재 시도·버전과 mutation_receipts의 서버 계산 request_scope를 저장해 공개/운영자·방문자 간 상태와 중복 요청 기록을 분리한다. 공개 페이지/API·운영자 응답에 Cache-Control: no-store를 적용하고 CDN/프록시·Service Worker의 캐시/오프라인 응답으로 인증·종료 검사를 우회하지 못하게 한다. 종료·인증 검사는 DB 조회·쓰기·receipt 반환보다 먼저 수행하며 직접 API와 기존 공개 세션 후속 요청도 종료 시각부터 차단한다. 개발 서버나 임시 SQLite를 그대로 공개하지 않는다. AC-08·AC-11 공개 확장의 구현 근거를 13.3의 검수표에 연결한다.)
- [ ] STORY 13.3: 기간 한정 공개·권한·종료 후 DB 보존 검수 (완료 확인: AC-08·AC-11 공개 확장을 최종 대조한다. 공개 전에는 격리 검수 환경의 제어 가능한 서버 시계로 20:59:59·21:00:00·21:00:01 KST 경계를 확인하고 공개 API에서는 시계를 주입할 수 없어야 한다. 실제 공개 후에는 종료 시각 뒤 실제 공유 URL을 확인한 결과까지 기록한다. 별도 Build와 배포 실행 조건 확인 후 종료 시각 전이라면 공개 조회·run/reset과 보호된 운영자 동작이 실제 DB 상태를 반영하고, 공개의 등록/수정/권리 확인/승인/취소/회사 생성/export 직접 API와 인증 없는 운영자 GET 요청은 거절되는 것을 확인한다. 방문자 A/B·운영자의 같은 과제에서 미생성 조회의 run_version0, 최초 run/reset 저장 버전1과 이후 범위별 단조 증가, 같은 request_id 재전송·충돌, 세션 위조·만료·CSRF 거절을 확인하며 다른 방문자/운영자의 현재 상태·이력과 snapshot/hash가 바뀌지 않아야 한다. 지정 5폭에서 역할별 허용 행동의 동등성, 재시작 후 저장·백업 복원을 확인한다. 2026-10-24 21:00 Asia/Seoul(12:00 UTC)부터 새 공개 UI/API 응답과 기존 공개 세션의 후속 요청이 차단되고 DB·개정본·snapshot·이력은 비공개로 보존되는지 서버 시각 경계로 검수한다. 실제 공유 URL·원본 호스트·캐시/프록시 경로에서 종료 후 요청과 과거 receipt 재요청이 거절되며 캐시/오프라인 응답으로 우회되지 않아야 한다. 시각이 이미 지났으면 공개 배포를 생략하고 비공개 검토 결과와 미실행 항목을 구분한다. 정적 화면만 동작한 것을 실제 7단계 시연 통과로 표시하지 않는다.)

## 후속 진행과 기록 원칙

- 각 STORY의 완료 확인을 실제로 본 뒤에만 `[x]`로 바꿉니다. 기존 파일·API 코드가 있다는 이유로 통과 처리하지 않습니다.
- 조건부 게이트가 해소되지 않으면 관련 STORY의 미완료 상태와 필요한 결정을 기록하고 영향 없는 앞선 작업만 진행합니다. 문서 작성 완료를 해당 정책 확정으로 간주하지 않습니다.
- C-06의 실제 AI STORY 12.1~12.6과 미채택 선택 손익은 미완료로 남기고 건너뜁니다. EPIC 13의 3 STORY는 기간 한정 해커톤 공개 시연으로 조건부 채택했으므로 영구 미채택으로 건너뛰지 않습니다. 별도 Build·실행 조건·공개 종료 시각을 확인하고 진행하며 종료 시각이 지났으면 공개 배포를 생략한 사유를 남깁니다. 선택 AI/손익·외부 계정 없음을 49개 필수 기능의 누락으로 세지 않으며 로컬 필수 완료와 실제 공개 시연/종료 검수 완료를 구분합니다.
- STORY가 많을수록 AI 사용량도 함께 늘어납니다. 한도가 있는 요금제라면 한 번에 2~3개씩 나누어 진행하세요. 중간에 멈춰도 체크박스와 조건 기록으로 이어갈 수 있습니다.
- 전체 문서 수정·검증과 사용자 최종 문서·계획 확정을 마쳤습니다. 모든 문서는 확정 상태이며 이후 수정사항은 구축 과정에서 관련 문서에 반영합니다. 정책 7/7을 다시 질문하지 않으며 최종 계획 확정과 Build 지시는 별개로 기록합니다. 실제 로컬 작업은 별도 Build 요청 후 STORY 1.1의 실행 환경 확인에서 시작합니다. 진행 기록은 이 문서를 기준으로 갱신하고 필요한 경우 `$vibe:status`로 확인합니다. 이번에는 코드·계정 가입·외부 호출·배포를 실행하지 않았습니다.
