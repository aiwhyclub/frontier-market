1. 인터넷 클라우드 관련 자료 수집 및 체계화

3. 같이 일할 전문가 모집 후 평가하여 데이터 업로드 작업
4. 카탈로그 제작 및 DB화
5. 도제로 만든 작업을 정제 및 검증하는 작업
6. FDE를 통한 시스템 구축/컨설팅
7. LLM 교육용 가상회사 구축

## 3. 개발계획 현재 상태

필수 기능 **49개**, 선택 기능 **7개**(선호 AI 2·추가 AI 4·가정 손익 1), 전체 ID 56개다. 기능별 STORY는 한 번씩 연결되어 있다.

계획은 **13 EPIC·70 STORY**, 모두 미완료다. 로컬 필수 60개는 필수 기능 49개+세팅/기반/검수 11개다. 선택 10개는 기능 7개+배포 3개다. **첫 목표는 EPIC 10까지 54 STORY**이며, EPIC 11의 나머지 필수 6개를 마쳐야 전체 로컬 필수 검수가 끝난다. STORY 11.6은 AC-01~13의 로컬 필수 범위를 대조하고, AC-08·AC-11의 공개 권한·세션 격리·21시 종료 확장은 STORY 13.2~13.3에서 최종 대조한다. EPIC 11 완료에 공개 배포를 요구하지 않는다.

현재 체크박스를 완료로 바꾸지 않는다. 최종 문서·계획 확인과 별도 Build 지시 후 첫 미완료 필수 STORY 1.1에서 로컬 환경을 확인하고 진행한다. **C-06 A로 실제 AI STORY 12.1~12.6은 첫 버전 보류·기본 건너뛰기**이며 선택 손익도 미채택이면 건너뛴다. AC-12의 현재 검수는 키/모델이 있어도 실제 AI 호출·AI 외부 전송·API 지출0인 수동/규칙·사람 경로이며 향후 실제 AI 검수와 구분한다. **EPIC 13의 3 STORY는 C-07 B의 기간 한정 공개 웹 시연을 위해 후속 Build에서 조건부 진행**한다. 영구 미채택으로 건너뛰지 않으며 권한·호스팅/비용/배포 수단·공개 종료와 DB 보존 조건은 13.1에서 구체화하고 13.2~13.3에서 공개 전에 검증한다. 이 공개 준비는 로컬 필수 착수를 막지 않는다. 선택 체크박스나 정책 답변만으로 AI 호출·가입/지출·실제 배포를 시작하지 않는다.

기존 `server.py`, `backend/`, `static/` 등의 코드는 중단된 미검증 초안이다. 문서와 일치하거나 이미 STORY가 완료된 것으로 간주하지 않는다. 별도 Build 때 내용을 확인하고 필요한 변경을 판단한다. 다른 사람의 변경을 임의로 삭제하거나 덮어쓰지 않는다.

실행 환경의 읽기 전용 메타데이터 점검에서 기본 `python3`는 3.15.0이고 해당 환경에는 Flask/Werkzeug가 설치되지 않은 것으로 확인했다. 현재 `requirements.txt`는 표준 라이브러리 전용 중단 초안이므로 Flask 명세로 그대로 재사용하지 않는다. TRD 기준 CPython 3.14.x·Flask 3.1.3·표준 sqlite3를 적용할 전용 가상 환경과 정확한 패치/전이 의존성 고정·호환성 확인은 별도 Build 후 STORY 1.1에서 수행한다. 이 점검으로 환경·파일을 바꾸거나 앱을 실행하지 않았다.

## 4. 특히 유지할 기술 경계

- 승인 전문가만 원시 업로드 가능. 이때 catalog 연결은 선택이며 정제·생성 전에 연결한다.
- 원문/생성 초안/채택 교정본/사람 승인은 분리한다. AI가 승인·권리 확인을 대신하지 않는다.
- 원천·전문가 제공 동의·작업의 목적/파생/배포/기간 제약을 교집합으로 검사한다. 미확인·만료·철회는 영향받는 생성/추가 export HOLD다.
- C-05 A: 지정 운영책임자1명이 권리증빙 확인·작업 검증·승인 취소·재검토를 각각 별도 기록하며 대상 버전·사유·근거·담당자·일시는 필수다. 입력 자체는 권리 부여나 독립 심사를 뜻하지 않는다. STORY 6.1·7.5·9.7·9.11에서 분리 기록과 보류/재검토를 검수한다.
- 특정 과거 승인을 취소하면 그 승인 ID를 사용하는 현재 작업의 신규 생성과 해당 snapshot의 추가 export를 HOLD한다. 보완 후 새 검토를 별도 기록하며 다른 유효한 승인은 보존한다. 과거 취소·원래 판정·패키지를 덮어쓰거나 자동 복구하지 않는다. 로컬 JSON 다운로드도 현재 권리/검토 검사를 통과해야 하며 외부 전달 허용을 뜻하지 않는다.
- `record version`은 개정 번호, `material_hash`는 실제 내용, `input_hash`는 사람 검토 입력의 동일성이다. grant는 존재하는 과거 버전과 그 material hash에 연결한다. 상태만 바뀌면 같은 내용 권리를 반복 등록하지 않으며 실제 내용 변경은 자동 승계하지 않는다. TRD §3.2.1의 반례 표를 유지한다.
- 과거 개정본과 회사 snapshot은 불변이다. 현재 권리/검토·실행 상태는 별도로 관리하며 내보내기 직전에 현재 조건을 다시 확인한다.
- 자료 원문·근거와 작업 원문·근거의 개정은 사유·담당자를 남긴 새 버전/개정 사건으로 저장하고 이전 원문/근거·검토 이력·과거 회사 snapshot을 보존한다. STORY 3.3·7.6에서 수정 후 재조회와 현재 작업 재검토를 확인하고 7.4의 교정본 저장과 구분한다. S4 발굴 6축과 선택 매체 참조는 기존 STORY 5.3·5.4의 필수 검수로 유지한다. 세 의견의 내용·처리 상태와 보완 대상 변경 후 재조회는 STORY 10.3·10.4와 AC-10에서 확인한다.
- task 실행/reset은 선택 과제의 현재 시도만 바꾸고 다른 과제·이전 시도·snapshot/hash를 보존한다. 공개 방문자의 run/reset은 방문자별 합성 시도로 분리하고 다른 방문자/운영자의 상태나 snapshot을 바꾸지 않는다.
- C-01 A의 내부 운영 도구 + Flask·SQLite·기본 웹을 유지하고 C-07 B의 해커톤 공개 시연을 후속 범위로 추가했다. 공개 방문자는 조회·과제 run/reset만 가능하며 등록·수정·권리 확인·승인·회사 생성·export는 운영자 보호 영역이다. 직접 API 우회도 차단한다. 외부 전문가/구매자 계정은 추가하지 않고 운영자 보호는 호스팅/서버 인증 경계로 제공한다. 지원 버전·의존성·실행 설정은 별도 Build 지시 후 STORY 1.1에서, 호스팅/비용/배포 수단·인증·세션 기술은 EPIC 13에서 공개 전에 확인·검증한다. 공개 DB는 로컬 운영·검수 DB와 분리한 합성 전용이며 공개 prefix API 외 운영자 경로는 GET을 포함해 기본 인증한다. TRD의 서명·만료 쿠키/nonce·CSRF 보호, 방문자별 현재 시도·버전과 요청 중복 기록의 분리는 STORY 13.2~13.3에서 검수한다. 비용 예시는 구매/구독 지시가 아니다.
